# Configuration and USB interface — schematic capture

## Boot path

The FPGA will use master SPI to load its CRAM from a 3.3 V serial flash. In the [SG48 pinout](https://www.latticesemi.com/view_document?document_id=51971), `SPI_SO` is pin 14, `SPI_SCK` pin 15, `SPI_SS` pin 16, and `SPI_SI` pin 17. `SPI_SO` drives flash data input, flash data output drives `SPI_SI`, and the clock and chip select are shared. `SPI_SS` must be high when `CRESET_B` is released to select master SPI. The [Lattice hardware checklist](https://www.latticesemi.com/view_document?document_id=47779), section 3, recommends 10 kΩ pull-ups on `SPI_SCK` and `SPI_SS` in this mode. `CRESET_B` is pin 8; `CDONE` is pin 7 and needs a pull-up sized for the configuration clock and trace capacitance.

The [Lattice programming note](https://www.latticesemi.com/view_document?document_id=46502), section 9, lists a 104,161-byte bitstream for the UP5K, so a flash with at least 833,288 bits is required. It must support 0x0B Fast Read with a 24-bit address and eight dummy bits, and operate at the FPGA configuration-clock rate. Support for 0xAB wake and 0xB9 deep power-down is desirable. Its power-on command-ready time must be checked; holding `CRESET_B` until the flash is ready is a valid mitigation. A captured candidate is Winbond W25Q16JVSSIQ (16 Mbit, 2.7–3.6 V, SOP-8), but its exact orderable status, detailed command/power-up timing, and footprint still need to be checked against its own data sheet. Its `CS_N`, `DO`, `DI`, and `CLK` connections in the [partial schematic](../hardware/power_config.tsx) follow the standard SOIC-8 SPI pin map. `/WP` and `/HOLD` have separate 10 kΩ pull-ups. No flash part is frozen.

## Host programming ownership

FT2232HL channel A is reserved for MPSSE flash programming. [FTDI AN_114](https://ftdichip.com/Support/Documents/AppNotes/AN_114_FTDI_Hi_Speed_USB_To_SPI_Example.pdf) maps ADBUS0/pin 16 to clock, ADBUS1/pin 17 to MOSI, ADBUS2/pin 18 to MISO, and ADBUS3/pin 19 to chip select. Channel B is reserved for candidate-data UART and later BBO readback; its UART TXD is BDBUS0/pin 38 and RXD is BDBUS1/pin 39 in the [FT2232H data sheet](https://www.ftdichip.cn/Support/Documents/DataSheets/ICs/DS_FT2232H.pdf). The schematic maps these UART nets to FPGA SG48 pins 12 and 11 respectively, the bank-2 pins facing the FT2232H. The timing-probe PCF now places its UART input on pin 12; the final RTL top is still to be written.

The FTDI outputs must be isolated from the shared flash bus outside a programming operation. [FTDI AN_184](https://www.ftdichip.cn/Support/Documents/AppNotes/AN_184%20FTDI%20Device%20Input%20Output%20Pin%20States.pdf) shows that channel-A pins have reset/enumeration and active functions that are not guaranteed to remain high impedance in every host state. ADBUS2 is an RTS# output in the initial UART mode, so even flash MISO is isolated. U9, an active-high-enable SN74LVC126A, buffers all four channel-A SPI signals. Its four OE pins share `PROG_OE`. U10, an SN74LVC1G02 NOR gate, produces `PROG_OE = NOR(FPGA_RESET_N, PROG_REQ_N)`. Therefore both the host request on ACBUS7/pin 34 and the **actual** FPGA `CRESET_B` net must be low to connect FTDI to the flash. R40 pulls `PROG_REQ_N` high and R42 pulls `PROG_OE` low. ACBUS6/pin 33 drives Q1, an NMOS that can pull the supervisor's `MR` low; R41 keeps Q1 off when the host pin is high impedance. Q1 never drives `MR` high.

| State | FPGA `CRESET_B` | FTDI-to-flash drive | Flash owner |
| --- | --- | --- | --- |
| Power ramp | Held low by rail supervision | Disabled by request pull-up | None |
| FPGA boot/run | Released high | Disabled | FPGA during boot; idle afterward |
| Flash programming | Held low by host reset control | Enabled after reset is low | FT2232H channel A |
| Programming exit | Remains low until host drive is disabled | Disabled first | None, then FPGA on reset release |

The planned host sequence is: set ACBUS6 high to assert the supervisor's manual reset; allow the specified reset response time; set ACBUS7 low to request the SPI buffers; erase/write/verify the flash; set ACBUS7 high to disable the buffers; set ACBUS6 low to release reset; then check `CDONE`. The hardware NOR gate enforces actual-reset-low before the buffers turn on; the host has no direct `CRESET_B` readback in the current schematic. The 10 kΩ pulls establish a safe state when the FTDI GPIOs are high impedance or the USB device resets. A host process crash while those GPIOs remain actively driven need not clear them; recovery from that state still needs a host watchdog or manual intervention. The table is a schematic-level design intent; timing and failure behavior have not been physically tested. Pin-level source, interlock and EEPROM review is in [usb-ftdi-review.md](usb-ftdi-review.md).

## FT2232H support circuit

The [FT2232H self-powered reference](https://www.ftdichip.cn/Support/Documents/DataSheets/ICs/DS_FT2232H.pdf), Figure 6.3, supplies `VREGIN`, `VPLL`, `VPHY`, and all four `VCCIO` pins from the board's 3.3 V rail. Its internal `VREGOUT` supplies the three 1.8 V `VCORE` pins with at least 3.3 µF of local filtering. The schematic includes the 12 MHz crystal, fixed 16-bit 93LC46B EEPROM, USB D+/D− and `REF` support connections, reset, USB-C sink CC resistors, ESD protection and local decoupling. USB VBUS reaches only a 4.7 kΩ/10 kΩ divider for `PWRSAV#` sensing. The EEPROM must be programmed for self-powered operation and the FTDI power-save option; its actual image and programming procedure remain to be created. The FTDI reference's power-save behavior with channel A in MPSSE mode and channel B in UART mode needs bench verification.

The FPGA clock source is a 48 MHz, 3.3 V [Abracon ASE-48.000MHZ-LC-T](https://abracon.com/Oscillators/ASEseries.pdf) CMOS oscillator, connected to SG48 pin 35 (`IOT_46b_G0`) with its tri-state pin pulled high to run. Its data sheet recommends about 10 nF across VDD/GND; C26 provides 100 nF. The 48 MHz timing assumption still lacks routed closure in the initial FPGA probe; see [synthesis evidence](synthesis.md). Oscillator startup, clock quality, and IO voltage levels are not physically measured.

The combined schematic has a generated netlist with targeted FPGA and FTDI pin checks. Package footprints and the programming circuit have not been physically validated, and no complete PCB exists.
